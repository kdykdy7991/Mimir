## 2. 风险与边界

- **Query 性能**：hybrid 检索 + rerank 在 v0.2 同步路径下可能有 P95 spike；如果 > 3s，需要在 v0.2 后期切到「Query 任务化」（同步 → 异步，复用批次 2 的 TaskTracker）。**v0.2 冻结前必跑一次基线**。
- **Trace 持久化**：现有 `tests/smoke/run_smoke.py` 提到 JSONL = JSON Lines 日志，可能需要新增 SQLite 表或保留 JSONL 索引。**v0.2 决定**：JSONL 全文扫描对 local scale 足够。
- **Image 字节大小**：image 实际是 PDF 抽出的位图（PNG / JPEG），单图一般 < 5 MB；但 v0.2 不限大小，统一靠反代层防 DoS。
- **上传 + 查询跨集合**：当前 storage 只有「default」单集合，document_id 按 (collection, source_path) 派生。Query 端点要支持非 default 集合，需 `HybridSearch` 接受 collection 名 / 索引名参数；**先确认是否已支持**，否则第 6 项要加。

## 4. 实际进展（由维护者持续填写）

### 4.1 探索结果

（2026-07-31 记录）

1. **QueryService / HybridSearch**：`QueryService.search(query, top_k=5, filters=None, trace=None)` → `QueryResult(chunks=list[RetrievalResult], latency_ms)`。`RetrievalResult` 带 `chunk(id/text/metadata/source_ref)`、`score`、`rank`、`source`。**HybridSearch 无 mode 分支**（永远 dense+sparse+RRF），但暴露 `.dense` / `.sparse` / `.query_processor`，QueryService 可直接调用实现 dense/sparse 模式。rerank 未接入 HybridSearch 流（`enable_rerank` 在 v0.2 为 no-op）。
2. **Trace**：`TraceContext`（uuid4 trace_id、trace_type、stages=[{name,ts,...}]、started_at/finished_at、`to_dict()` 含 total_elapsed_ms）；持久化靠 `TraceCollector` 写 JSONL。**web 侧没有按 id 查 trace 的索引**；dashboard 的 `TraceService` 是全文扫描 JSONL。batch 2 的 `IngestionService._run_worker` 跑 pipeline **不带 trace** → ingestion trace 需要接线（trace_id = task_id）。
3. **ImageStorage**：`get(image_id)` → `ImageRecord(file_path,...)`；字节在磁盘 `data/images/<coll>/{id}.{ext}`。`DocumentManager` 只私有持有 `_images`，**无公开访问器** → 需加 `image_storage` property。MIME 可从扩展名映射（png/jpg/jpeg/gif/webp）。
4. **现有 schema**：`queries.py`（QueryRequest/Response 完整）、`traces.py`（TraceResponse 完整）、`images.py`（仅 ImageMeta，字节用 FileResponse）均已存在——**无需改字段**。错误码：`QUERY_NOT_FOUND` / `IMAGE_NOT_FOUND` / `COLLECTION_NOT_FOUND` / `UPSTREAM_ERROR` 已有；`INGESTION_NOT_FOUND` **未预留**（plan 假设有误），需新增。
5. **Collection 绑定**：引擎在 boot 时按单 collection（default）构建。非 default 集合的 query 会打到 default 索引 → 记录为已知限制。诊断计数可从 trace 的 `dense`/`sparse` finish 事件 `n_out`、`trim` 事件 `n_before` 读出；degraded 从 `dense_failed`/`sparse_failed`/`no_results` 等事件判定。

### 4.2 设计决策

（2026-07-31 记录）

- **Trace 存储**：新增 `TraceStore`（application 层）——内存 dict `trace_id → to_dict()` + JSONL 追加；`get()` 内存未命中时全文扫描 JSONL（本地规模足够，重启后早期 trace 仍可查）。路径 `{data_dir}/traces/traces.jsonl`。query_id == trace_id（服务端生成，不支持 client supply id）。
- **接线**：`QueryService` / `IngestionService` 构造器新增可选 `trace_store`；每次 query / 每次上传 worker 各记一条 trace。`ApplicationServices` 增 `trace: TraceStore` 字段；composition 建一个共享实例注入两侧。
- **Query mode**：QueryService.search 增 `mode` 参数——hybrid 走原 HybridSearch；dense/sparse 直接调 `.dense.retrieve(...)` / `.sparse.retrieve(...)`（sparse 用 query_processor 产 keywords）。embedding 失败在 dense mode 下抛 `EmbeddingError` → 路由转 502 `UPSTREAM_ERROR`；hybrid 下被 HybridSearch 内部降级（→ degraded 标记）。
- **Trace 端点语义**：query trace 查不到 → 404 `QUERY_NOT_FOUND`；ingestion：store 命中 → 200，store 未命中但 TaskTracker 里有该 task → 200 空 stages（时间戳取 task 记录），两者都无 → 404 `INGESTION_NOT_FOUND`（新错误类）。
- **Citation 映射**：`index`(1-based)、`chunk_id`、`document_id = document_uuid(collection, chunk.metadata.source_path)`、`document_name`=basename、`page=metadata.get("page")`、`text=chunk.text`、`scores` 只填当前来源的分数（hybrid→fusion，dense→dense，sparse→sparse，其余 null）、`images` 从 `metadata.images` 映射 `CitationImage(url=/api/v1/images/{id})`。
- **Diagnostics**：`duration_ms`=latency、`trace_id`、计数从 trace 事件读（见 4.1 第 5 点）、`degraded`/`degraded_reasons` 从失败事件映射。
- **Images**：image_id 先用 ChunkId 正则校验（`[A-Za-z0-9_-]{1,128}`）；查不到 → 404 `IMAGE_NOT_FOUND`；读字节 + 扩展名→MIME allow-list；`Cache-Control: public, max-age=86400`。ETag 推迟（v0.2 不做）。
- **DocumentDetail.last_query_id**：**推迟到 v0.3**（plan 标可选；需要 query registry，超出本批次范围）。
- **非 default 集合 query**：跑在 default 索引上，已知限制（见 4.1 第 5 点），handoff 记录。
