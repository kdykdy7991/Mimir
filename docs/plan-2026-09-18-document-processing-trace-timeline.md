# 文档处理 Trace 时间线开发计划

> 状态：第一阶段已完成
>
> 创建日期：2026-09-18
> 参考实现：WeKnora 文档详情内的 `knowledge-processing-timeline`，不是照搬其代码或视觉。

## 1. 目标

把摄取 Trace 从独立的运维查询页带回文档业务上下文。用户在文档详情即可回答：

1. 文档现在处理到哪一步；
2. 哪一步最慢、被跳过或失败；
3. 每一步的输入、输出与安全元数据是什么；
4. 失败后应该重试，还是去全局 Trace 继续诊断。

Langfuse 继续用于模型调用、Token、成本和跨请求分析；本功能负责应用内文档处理可解释性，两者不互相替代。

## 2. 本期范围

- 在文档详情“处理流程”卡片提供完整时间线入口；
- 新增可复用的文档处理 Trace 抽屉；
- 用 `started_at + duration_ms` 绘制相对时间瀑布；
- 展示 Trace/阶段状态、耗时、方法、Provider、尝试次数和跳过原因；
- 失败摘要固定在抽屉顶部；
- 阶段详情提供“概览 / 输入输出 / 元数据”三个视图；
- 运行中摄取 Trace 自动刷新，页面隐藏时降低刷新频率；
- 抽屉宽度支持拖动，并保存在浏览器本地；
- 保留跳转 `/traces` 的完整历史、筛选、重试与取消能力；
- 补齐组件测试和类型检查。

## 3. 数据契约与降级规则

本期只消费现有 `TraceResponse`：

- Trace：`status`、`attempt`、`error`、`total_latency_ms`；
- Stage：`started_at`、`duration_ms`、`status`、`method`、`provider`、输入/输出数量、错误与 `details`；
- 运行中阶段以当前时间计算可视宽度，但不修改服务端原始耗时；
- 缺少时间或详情时显示明确的空值，不推断不存在的数据；
- `details` 只在用户主动查看元数据时呈现，并过滤原型键。

当前契约没有 `span_id`、`parent_span_id`、模型 Token/成本和 Langfuse URL。因此本期是按时间排序的扁平瀑布，不伪造树形层级，也不提供假的 Langfuse 跳转。

## 4. 交互验收

- 文档存在 `last_task_id` 时，可在详情页打开处理链路抽屉；
- 抽屉打开后仍处于文档上下文，不发生整页跳转；
- 每个阶段的横条位置和宽度反映其在总链路中的相对时间；
- 点击阶段后可查看业务名称、原始阶段名、时间、状态和详情；
- 失败 Trace 无需滚动即可看到错误摘要；
- 运行中 Trace 会自动获得新状态，关闭抽屉后停止轮询；
- 键盘可关闭抽屉，遮罩点击可关闭，焦点按钮具有可访问名称；
- 原有“查看完整 Trace”入口继续可用。

## 5. 后续契约增强

第二阶段建议给 Trace Stage 增加：

- `span_id`、`parent_span_id`、`kind`，用于真实树形瀑布；
- `input`、`output` 的安全摘要，而不只是数量；
- `model`、`token_usage`、`cost`、`langfuse_trace_id/url`；
- Attempt 列表接口，让一次文档处理的多次尝试可在同一抽屉切换；
- 服务端事件流或增量游标，替换固定间隔轮询。
